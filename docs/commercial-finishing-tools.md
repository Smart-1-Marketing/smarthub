# Commercial Builder finishing tools

The Preview step now offers a scene rehearsal with a scrubber, measured speech lengths where available, rendered caption phrases, end-card text, and conservative safe-area guides. Captions are optional and use estimated phrase timing, not forced alignment. The rehearsal is a layout check, not a pixel-identical render; it cannot prove lip-sync, pronunciation or the final animation.

Finished renders capture their intended duration, dimensions and audio requirement at submission. The existing recovery scheduler downloads and inspects the output with FFprobe/FFmpeg. It checks actual streams, duration, dimensions and decoding, and flags black/quiet sections for human review. Hard failures block filing; unavailable checks and content warnings require explicit human confirmation. Older renders without a submission specification remain unverified rather than being compared against a draft that may have changed. Check results are tied to the output URL. Checks can be retried from the render card; temporary inspection failures use the existing recovery backoff.

Downloads are restricted to public HTTPS render/storage hosts, redirects are revalidated, file size is bounded at 150 MB, and inspection accepts MP4 containers with local-file protocols only. Fetching and decoding have time limits; these bounds may leave large or slow files unverified. Production already installs FFmpeg. This is not an automated judgment of visual quality or legal compliance.

Approved presets belong to one client. They capture brand details, pronunciation, casting choices and the end card, with an approving actor and source project. Applying them updates a draft only; approved projects and active media jobs cannot be changed this way. Existing media is retained and changed speech settings are marked stale. The presenter picker loads the saved casting selection only if the avatar remains available. Brand snapshots feed subsequent concepts/scripts without rebuilding the approved context.

Controlled variations require an approved source. Up to five alternative spoken lines can be previewed and created together. The preview identifies changed speech, reusable footage and the final render required. A source/edit digest rejects obsolete previews; locked scenes cannot be changed. Creating drafts does not call a provider. Existing brief/CTA/voice/duration variation tools also create drafts, persist changes correctly, and mark brief/duration changes as needing a new script.

The project spending panel consumes the existing provider meters. It counts recorded calls, failures and reused responses, with known dollar costs separated from unpriced usage. Render attempts are counted from saved jobs. Elapsed time is calendar time from creation to first approval, not hands-on editing time. Historical provider calls cannot be reconstructed, and reused assets retain their original production cost on the source project. The figures are neither an invoice nor a complete historical cost total.

Concepts and explicit creative reviews use `COMMERCIAL_CREATIVE_MODEL` (default `gpt-6-astra`) with low reasoning effort. Routine script writing and utility tasks retain the existing `commercial.text` setting. Reviews are reused only when the script, brief, brand, CTA and model match. No creative review rewrites the script. Existing OpenAI configuration supplies credentials; no new key is created. Availability and latency must be verified against the production account; choosing a more capable model does not guarantee a faster response. API compatibility was checked against [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model) on September 12, 2026.

New tables (`cb_render_inspections`, `cb_brand_presets`, `cb_production_usage`) are additive and created through the existing startup mechanism. No existing database columns are altered. Shared generation entry points establish project metering context for background work; request paths inherit it from the builder blueprint. No extra scheduler thread is created.

Validation includes isolated contract tests, existing commercial suites, and desktop/mobile browser checks. `test_commercial_finishing.py` includes a real synthetic-MP4 decoder check when FFmpeg is available. Provider calls are disabled in the local fixtures. A paid live acceptance test must still verify the default presenter/voice, pronunciation, lip-sync, captions and final output; synthetic tests do not establish these.
