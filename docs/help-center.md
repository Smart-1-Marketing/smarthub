# Hub account, notifications and help

The shared help script mounts the signed-in name, initials, Help link and personal notification bell on Hub and mounted tool pages. Notifications poll every 30 seconds while the page is visible. Read markers are stored per user in that browser; a change from processing to completed/failed becomes unread again. Radio completions come from attributed activity events. New video render submissions carry their actor and poll the existing render-status endpoint. New display jobs are captured from the renderer's acceptance response and polled through the authenticated proxy. Historical video events without an actor cannot be assigned retroactively. This is an in-app inbox, not an operating-system push service.

`/help` searches the existing help registry and walkthrough catalogue. The assistant uses retrieved help entries through the existing configured AI client and usage accounting. It cannot operate tools. Missing documentation or unavailable AI is shown explicitly. Every accepted question is saved before a paid call, with the answer, source keys and outcome added afterwards. Records live under the persistent data root in `help-questions/<user-key>/<id>.json`, using the existing JSON store/database mirror. Five questions per minute per user is the normal request limit.

The 18 recorded product lessons come from the existing partner Learning Library (`hub/partner_pages/learning-library.html`). All 18 YouTube links returned valid video metadata on September 8, 2026; results are in `help-tutorial-link-check.json`. Additional tutorials can be supplied through `help-tutorials.json` in the persistent data root, as an array with `title`, `url` (HTTPS), and optional `description`. Custom entries override duplicate URLs. Product lessons and Hub guided walkthroughs are labelled separately.

The Help Center embeds the same LeadConnector feedback form already opened by the bottom-right feedback tab. Questions and answers are retained for manual product/support review; they do not automatically train or change the model.

Validation: ten focused tests in `test_help_center.py` pass, as do Python compilation and JavaScript syntax checks. A local browser preview verified search filtering, initials, notifications, persisted read markers, and the loaded support form. Both existing help-layer suites pass with a writable Windows session directory, including 42 Hub integration checks. The full Linux CI and both CodeQL scans also passed on the feature PR before the version-only conflict with concurrent main changes was resolved. Provider rendering, live AI and form submission require configured services and were not exercised. Release target: v1.75.0. Production verification is recorded separately after deployment.
