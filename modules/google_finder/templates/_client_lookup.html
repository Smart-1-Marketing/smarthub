{# Client lookup and auto-fill, shared by every Google tool page. Each tool asked for the same thing in a different way: type a container id, or a property id, or a Google login and an account number. Nobody carries those around — they carry a client name. So this takes the name and fills in the ids from hub/google_index.py, which already holds every reachable Google resource joined to a client. Two things make it cheap enough to sit on every page: * It reads the STORED index, not Google. No sweep, no Tag Manager pacing, no waiting. The index is rebuilt every three hours by the scheduler. * Both requests go to the hub app, not to this module. That is deliberate and it is the mount trap in reverse: this page is served under /google, so a relative fetch would resolve inside the module and 404. The literal leading-slash paths below are checked by tools/linkcheck.py against the route table of whichever app owns the prefix. Usage, from a tool page, before the include: {% set lookup_platform = 'gtm' %} {% set lookup_fill = {'resource_id': '#gtm-lookup-q'} %} {% include "_client_lookup.html" %} `lookup_fill` maps a field on the matched resource to a CSS selector on the page. Anything the page does not name is simply not filled — a tool that gains an input later does not silently start receiving values it cannot use. #}
